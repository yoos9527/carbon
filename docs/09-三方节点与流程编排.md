## 3. 节点契约 DSL v2

### 3.1 `CallNode` 目标定义

`carbon-framework/carbon-framework-dag/src/main/java/com/carbon/framework/dag/dsl/node/CallNode.java`：

```java
public record CallNode(String id, String label, String connector, String operation,
                       Map<String, Object> input,              // 兼容保留，模板串形态
                       List<ParamMapping> inputMappings,       // 新增：入参契约
                       Map<String, String> output,             // 兼容保留，JSONPath 形态
                       List<OutMapping> outputMappings,        // 新增：出参契约
                       Fallback fallback,                      // 新增：备用数据源
                       CachePolicy cache,                      // 新增：节点级缓存
                       Long timeoutMs,                         // 新增：节点级超时
                       boolean skipOnTimeout,                  // 新增：超时自动跳过
                       OnError onError, Retry retry) implements NodeDef
```

约束（构造器里断言，与既有 `Nodes.requireId` 同风格）：
- `inputMappings` 与 `input` **不能同时非空**（否则渲染顺序歧义）。
- `timeoutMs == null` 时回落到 `DagDsl.timeoutMs`。
- `skipOnTimeout == true` 时 `onError` 必须为 `CONTINUE`（语义一致）。

### 3.2 新 record（同包 `dsl/node/`）

```java
/** 入参契约：name = 服务侧参数名（来自 Operation 的入参定义）；value = 取值来源 */
public record ParamMapping(String name,
                           ValueType type,      // STRING|INT|DECIMAL|BOOL|DATE|ARRAY|OBJECT
                           boolean required,
                           ValueRef value) {}

/** 取值来源：VAR 引用全局出参池的字段名；CONST 用字面量 */
public record ValueRef(ValueRef.Kind kind, String ref) {
    public enum Kind { VAR, CONST }
    public static ValueRef var(String name)   { return new ValueRef(Kind.VAR, name); }
    public static ValueRef constOf(String v)  { return new ValueRef(Kind.CONST, v); }
}

/** 出参契约：field = 服务返回字段（Operation 的出参定义）；name = 写入全局池的名字；jsonPath = 抽取路径 */
public record OutMapping(String field, String name, String jsonPath) {}

/** 备用数据源：主源异常时切换；interruptOnFail = 备用也失败时是否中断决策 */
public record Fallback(String connector, String operation,
                       List<ParamMapping> inputMappings,
                       boolean interruptOnFail) {}

/** 节点级缓存：ttlSeconds 不得超过服务级全局 TTL（校验期拦） */
public record CachePolicy(boolean enabled, Long ttlSeconds, boolean localFirst) {
    public static final CachePolicy OFF = new CachePolicy(false, null, false);
}
```

`OnError` 增一态，变成三态：

```java
public enum OnError { STOP, CONTINUE, FALLBACK }
// STOP     = 中断（参考系统：调用异常时自动中断决策）
// CONTINUE = 跳过，节点出参置 null 仍写入池，避免下游空指针（参考系统：超过 N 秒自动跳过）
// FALLBACK = 切备用数据源，备用失败再看 Fallback.interruptOnFail
```

### 3.3 DSL JSON 示例（一个真实形状的三方节点）

```json
{
  "type": "CONNECTOR_CALL",
  "id": "n_qcc_lose",
  "label": "企查查-失信核查",
  "connector": "qcc",
  "operation": "historyShixin",
  "inputMappings": [
    {"name": "entName", "type": "STRING", "required": true,  "value": {"kind": "VAR",   "ref": "applyEntName"}},
    {"name": "pageNo",  "type": "INT",    "required": false, "value": {"kind": "CONST", "ref": "1"}}
  ],
  "outputMappings": [
    {"field": "total",   "name": "shixinTotal", "jsonPath": "$.result.total"},
    {"field": "records", "name": "shixinList",  "jsonPath": "$.result.items"}
  ],
  "fallback": {
    "connector": "tianyancha", "operation": "historyShixin",
    "inputMappings": [
      {"name": "name", "type": "STRING", "required": true, "value": {"kind": "VAR", "ref": "applyEntName"}}
    ],
    "interruptOnFail": false
  },
  "cache": {"enabled": true, "ttlSeconds": 86400, "localFirst": false},
  "timeoutMs": 3000,
  "skipOnTimeout": true,
  "onError": "FALLBACK",
  "retry": {"maxAttempts": 2, "backoffMs": 200}
}
```

### 3.4 兼容策略

- 老 DSL 只有 `input`/`output` → `inputMappings`/`outputMappings` 为 `null` → 执行体走原有模板渲染 + JSONPath 抽取路径，**行为一字不变**。
- 新 DSL 只允许填契约字段；同时填两种 → 编译期 `DagCompileException`。
- 反序列化用 Jackson 默认 `@JsonIgnoreProperties`，新字段缺省为 `null`，不需要写迁移脚本。

## 4. 执行语义

### 4.1 五步流水（`FlowNodeHandler` 的 `CONNECTOR_CALL` 分支）

```
1 组装入参   按 ParamMapping 逐个取值：VAR → OutputPool 取值；CONST → 字面量
             required 且取值为空 → PARAM_REQUIRED_MISSING（校验期就该拦住，这里是兜底）
2 缓存查找   cache.enabled → key = "flow:node:" + operation + ":" + sha256(canonicalJson(入参))
             命中 → 出参直接从缓存写池，stepRun.cacheHit = true，结束（不产生三方成本）
3 主调用     InvokeRequest(connectorCode, operationCode, input, envCode, ...) 交给既有 InvokeService
             成功 → 转 5
4 异常处置   见 4.2 矩阵
5 出参写池   按 OutMapping 抽取 JSONPath → OutputPool.put(name, value, nodeId, type)
             重名 → OUTPUT_NAME_DUPLICATE（校验期拦，运行期兜底抛错）
```

### 4.2 异常矩阵（这是三态的具体含义）

| 场景 | `onError=STOP` | `CONTINUE` | `FALLBACK` |
|---|---|---|---|
| 主源技术故障（连接失败/读超时） | 整图 FAILED | 节点 SKIPPED，出参置 null 入池 | 调备用源 |
| 主源业务失败（4xx/5xx，`CallNode` 注释 :14-15 定义为业务结果） | 整图 FAILED | SKIPPED | 调备用源 |
| 主源超时且 `skipOnTimeout=true` | 节点 SKIPPED（优先于 STOP） | SKIPPED | SKIPPED |
| 备用源成功 | — | — | 节点 SUCCESS，`stepRun.fallbackUsed=true` |
| 备用源失败且 `interruptOnFail=true` | — | — | 整图 FAILED |
| 备用源失败且 `interruptOnFail=false` | — | — | 节点 SKIPPED，`partial` 计入 FlowRun |
| 重试耗尽（`Retry.maxAttempts`） | 走上面各态 | 走上面各态 | 走上面各态 |

`FlowRun.status` 沿用既有四态 `RUNNING|SUCCESS|PARTIAL|FAILED`（见 `V1__init.sql:132` 注释）：只要有节点 SKIPPED 但流程跑完 → `PARTIAL`（与 `docs/08-数据接入平台.md` §1 "单个接口失败不中断流程；`partial`+`errors[]`"一致）。

### 4.3 缓存键与 TTL 收敛

参考系统三层收敛语义（实测原文）必须照抄：

| 层 | 配置位置 | 约束（原文） |
|---|---|---|
| 服务级 | `Operation` 表新增 `cache_enabled` / `cache_ttl_seconds` | 服务级开关是总闸 |
| 节点级 | `CallNode.cache.ttlSeconds` | `个性缓存时长不可超过全局缓存时长，当前全局时长为 {X}` |
| 开关关闭后 | — | `该三方未打开缓存开关，无法配置个性缓存时长` / `该三方缓存开关已关闭，个性缓存失效` |

实现：校验期比大小（`CACHE_TTL_EXCEEDED`）；运行期读 `Operation` 的开关，若全局关闭则**忽略**节点级配置（不报错，正是"个性缓存失效"的语义）。
`localFirst` 本期只落库不实现（P2 才做进程内一级缓存），文档里要写清，避免死配置误解。

### 4.4 trace 落库

`flow_step_run` 加 3 列（`V6__node_contract.sql`）：


## 5. 全局出参池

`carbon-modules/carbon-flow/src/main/java/com/carbon/modules/flow/executor/OutputPool.java`（新建）：

```java
public final class OutputPool {
    private final Map<String, Object> values;   // 扁平池，等价参考系统"策略所有节点出参汇总"
    private final Map<String, Owner>   owners;  // name -> (nodeId, ValueType)

    public void put(String name, Object value, String nodeId, ValueType type); // 重名即抛
    public Object get(String name);
    public Optional<ValueType> typeOf(String name);   // 给条件下拉 + 表达式类型校验用
    public Map<String, Object> snapshot();
}
```

为什么必须全局扁平（决策 2A 的落地依据）：
- 参考系统原文 `（策略所有节点出参汇总，包括前置服务与决策补充服务出参）` —— 下游判断节点的 `选择输入字段` 下拉列的就是这张表；
- carbon 的 `vars` 本来就是扁平 `Map`，改成 `nodeId.field` 路径反而要改 `TemplateRenderer` 的取值语法（`{{vars.x}}`），代价大收益小；
- 重名风险用校验期硬拦（`出参字段名不能相同`），不留在运行期。

**入参引用一致性**：`ValueRef.VAR` 引用的名字必须在"可达前序节点"的出参里存在，否则 `REFERENCE_INVALID`（复用现有码）。可达性判断复用 `GraphValidator` 已有的后支配/前驱分析（`GraphValidator.java:326 checkConvergence` 附近）。

## 6. 校验规则（新增 `ValidationCode`）

| 新码 | 触发条件 | 对应参考系统原文 |
|---|---|---|
| `PARAM_REQUIRED_MISSING` | `required=true` 但 `value == null` | `入参存在未填写项` |
| `MAPPING_INCOMPLETE` | 入参/出参列表里存在 `name` 或 `field` 为空的行 | `请完成入参 / 出参字段映射` |
| `OUTPUT_NAME_DUPLICATE` | 两个节点的出参 `name` 相同，或同节点内重复 | `出参字段名不能相同` |
| `FALLBACK_OUTPUT_NOT_SUPERSET` | `fallback.outputMappings` 的 `name` 集合 ⊉ 主源 `name` 集合 | `备用数据源出参需包含主数据源出参，可能影响后续流程` |
| `CACHE_TTL_EXCEEDED` | `cache.ttlSeconds > operation.cacheTtlSeconds` | `个性缓存时长不可超过全局缓存时长` |
| `CACHE_ON_DISABLED_SERVICE` | `cache.enabled` 但服务级 `cache_enabled=0` | `该三方未打开缓存开关，无法配置个性缓存时长` |
| `NODE_NAME_TOO_LONG` | `label.length() > 16` | `节点名称长度不得超过16` |
| `INPUT_CONFLICT` | 同时填了 `input` 与 `inputMappings` | —（carbon 自有） |

新增 8 个码，现有 26 个不动。`FALLBACK_OUTPUT_NOT_SUPERSET` 是纯集合判断（`main.names ⊆ fallback.names`），最容易漏但最致命：漏了它，降级后下游条件里的字段会静默变 null。

## 8. 状态机与双区（决策 5B）

### 8.1 版本状态机

| 状态 | 含义 | 允许动作 | 参考系统原文 |
|---|---|---|---|
| `SAVED` | 已保存（编辑区草稿覆盖了已有版本） | 提交审核、发布 | `已保存` |
| `DRAFT` | 已暂存（未提交） | 继续编辑、丢弃 | `已暂存` |
| `PENDING_REVIEW` | 待审核 | 审核通过 / 驳回 | `待审核` |
| `PENDING_RECHECK` | 待复核（二级审批） | 复核通过 / 驳回 | `待复核` |
| `ONLINE` | 已上线（运行区生效版本） | 下线、选为主版本 | `已上线` |
| `OFFLINE` | 已下线 | 回滚上线 | `已下线` |
| `ABNORMAL` | 状态异常 | 人工修复 | `状态异常` |

转换：`DRAFT → SAVED → PENDING_REVIEW → PENDING_RECHECK → ONLINE → OFFLINE → ONLINE`（回滚）。
同一 `flowId` 下 `ONLINE` 必须唯一；`is_primary` 标"主版本"，切换主版本只改标记不复制 DSL。

### 8.2 双区

| 区 | 数据来源 | 可做 |
|---|---|---|
| 运行区 | `flow.publishedVersion` 对应的 `flow_version.dsl` | 查看、调用报告、下线、版本历史 |
| 编辑区 | `flow.draftDsl` | 编辑、暂存、保存、提交审核、画布内试跑 |

保存动作语义（照抄参考系统）：保存 = 覆盖编辑区草稿；暂存 = 只存草稿不生成版本；发布 = 从草稿生成新 `flow_version` 并推进状态机。
试跑只允许对**已保存**的草稿跑（参考系统原文 `仅支持测试已保存的策略…`），试跑结果不落 `flow_run`（落 `flow_run` 需要 `trigger_type=manual` 且标记 `dryRun`，与 `InvokeService.dryRun` 对齐）。

## 9. 前端设计（`carbon-ui`）

### 9.1 依赖
