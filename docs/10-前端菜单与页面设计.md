# 10 · 前端菜单与页面设计（配置域）

> 版本 v1.0 ｜ 范围：`carbon-ui` 配置域（连接器 → 数据源服务接口 → 流程编排）＋ 运行域只读页
> 上游文档：`docs/09-三方节点与流程编排.md`（节点契约、DSL v2、校验码、状态机）
> 明确排除：合作方管理 / 合同计费 / 规则集 / 评分卡 / 模型 / 名单 / 注册服务 / 产品接入 / 渠道接入

---

## 0. 结论先行

1. **后端配置域接口基本齐全**（`/api/connectors`、`/api/connectors/{id}/operations`、`/api/flows` 含 validate/publish/versions/rollback/run/run-async、`/api/flow-runs` 含 SSE），本期**缺的主要是前端页面**。
2. 唯一需要**新建后端表**的是「ETL 处理器」；其余新增页都是对既有接口的重新组织。
3. 菜单按 **配置域 / 运行域 / 调度 / 系统** 四段切，同一份数据不靠页面内 Tab 混在两个菜单里。
4. 画布**不进菜单**：它是全屏工作台，从流程列表点进。

**旧路由迁移**：`/connectors/:id/operations`（接口与试调，`showLink:false`）合并进 `/services`；`/flow/runs` → `/flow-runs`。旧路径不做重定向（未上线，无外部链接）。

### 1.1 三条切分原则

| 原则 | 说明 |
|---|---|
| 配置域 / 运行域在**菜单层**分开 | 改配置的人与看结果的人往往不是同一个；混在页面 Tab 里会让"改"和"看"共享同一套筛选条件 |
| 菜单顺序 = **供应商 → 接口 → 流程** 三层递进 | 与 `docs/08` 的三层模型一致：连接器（谁）+ 接口（调什么）+ 流程（怎么串） |
| 画布不进菜单 | 画布必须独占视口；做成菜单项会出现"点进去先选流程"的空页 |

### 1.2 为什么「连接器」与「数据源服务接口」是两个菜单

- 连接器 = **网络与鉴权**（一个供应商一份：baseUrl、鉴权、证书、超时默认值）
- 数据源服务接口 = **业务契约**（一个接口一份：path、入参 schema、出参映射、脚本、缓存、限流）

混在一起的后果：改密钥和改出参映射出现在同一张表单上，权限无法分离，且接口列表会被连接器字段淹没。

## 2. 逐菜单规格

### 2.0 概览 · `/welcome` ｜ 后端现成 `GET /api/stats/overview`

**职责**：一屏看清系统健康，不需要逐页点。

**页面结构**
- 6 张计数卡：连接器、接口、流程、应用、任务、幽灵 RUNNING（多实例宕机残留，见后端注释）
- 趋势图：近 N 天 `total / failed / successRate / avgMs / p95Ms`
- 来源占比：`CONSOLE` 试调 / `GW` 网关 / `FLOW` 编排

**注意**：`carbon-ui/src/api/stats.ts` 注释已声明「后端一次算完所有块，避免 6 张卡 6 个请求」，**禁止**拆成多个列表接口。

**验收**：刷新一次只发 1 个 `/api/stats/overview` 请求（Network 面板核对）。

### 2.1 连接器 · `/connectors` ｜ 后端现成

**职责**：维护上游系统（供应商）的技术侧配置。

**数据源**：`connector`（code / name / category / base_url / default_headers / timeout_ms / retry / status / remark）+ `connector_auth`（鉴权方式、密钥密文、证书）

**页面结构**：`PureTableBar` 列表 + 新建/编辑抽屉 + 行内启停。
行操作：编辑 / 复制（`POST /connectors/{id}/copy`）/ 启停（`PUT /connectors/{id}/status`）/ 删除 / **查看其接口**（跳 `/services?connectorId=x`）

**关键字段约束**
- `code`：唯一、不可改（被 `flow` DSL 里的 `connector` 引用）
- `base_url`：不含路径，路径交给接口的 `path`
- `timeout_ms` / `retry`：连接器级默认，接口级可覆盖（空 = 继承）

**验收**：新建 → 配鉴权 → 从该行跳到 `/services` 能看到空列表并可直接新增接口。

### 2.2 数据源服务接口 · `/services` ｜ **改造**（后端已有，接口是嵌套路径）

**职责**：本期最核心页。运营视角的「接口资产总账」：跨连接器看全部接口、谁有契约、谁配了缓存、谁已上线。

**数据来源**：`connector_operation`

**后端现状（关键约束）**：接口是**嵌套**的 —— `/api/connectors/{connectorId}/operations`，**没有** `GET /api/services`。两条路：

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A（本期采用）** | 前端聚合：先拉连接器列表（分页取全量，量级几十），再对每个连接器并发拉 operations，前端合并 + 本地筛选分页 | 不动后端；连接器数量在"几十"量级可接受 |
| B（后续优化） | 后端加 `GET /api/services?keyword=&method=&status=` | 列表筛选/分页更干净，但本期不做 |

方案 A 的实现约束：并发上限 6（`Promise.all` 分批）；连接器 >50 时降级为"必须先选连接器"。

**列表形态**：**卡片网格**（对齐参考系统的数据源服务接口列表），不用表格。
卡片字段：接口名称、`code`、方法徽标（GET/POST…）、所属连接器、状态点（草稿 / 已上线 / 已下线）、缓存开关、是否有契约（`input_schema` + `response_extract` 齐全 = 有）

**图片/网格切换**：右上角提供「表格视图」切换（排障时表格更快）。

**过滤条**：接口名称关键词 / 连接器 / 方法 / 状态 / 仅看无契约

**详情页 5 个 Tab**（`/services/:connectorId/:operationId`，抽屉或子页）

| Tab | 内容 | 字段 |
|---|---|---|
| 1 基础 | 请求定义 | `name` `code` `method` `path` `query_params` `headers` `body_type` `body_template` `status` |
| 2 契约 | 入参 schema + 出参映射 | `input_schema`（docs/09 §7 新增列）`response_extract`（已存在：`[{name, jsonpath, default}]`） |
| 3 脚本 | Groovy 前置/后置 | `pre_script` `post_script` `script_timeout_ms` |
| 4 超时与缓存 | 运行策略 | `timeout_ms`（空=继承）`retry`（JSON，空=继承）`cache_enabled` `cache_ttl_seconds` |
| 5 试调 | 真实调用一次 | 填参数 → 展示脱敏后的 request / response / 耗时 |

**为什么契约 Tab 重要**：`docs/09` §9.4 的属性面板里「入参字段」「出参字段」两个下拉，其数据源就是这里。没有契约，画布只能手填 JSONPath。

**试调**：当前后端**没有** `operations/{id}/test` 端点。本期两种选择：

- **A（本期）**：复用 `POST /api/flows/{id}/run` —— 临时构造单节点 DSL 跑一次（脏、不推荐）
- **B（本期）**：**暂不实现试调 Tab**，标注「待后端提供 `POST /api/connectors/{cid}/operations/{oid}/test`」

> 建议 B。三个 Tab 先做扎实（基础 / 契约 / 脚本），试调等后端。

**验收**
1. 某连接器下新增接口并配好 `input_schema` 后，`/services` 卡片出现「有契约」标记
2. 切换连接器筛选后，卡片数 = 该连接器接口数
3. 编辑保存后刷新，字段不丢（`body_template` 里的换行/引号往返不损坏）

### 2.3 ETL 处理器 · `/etl-handlers` ｜ **新增，需新表**

**职责**：把现在内联在 `connector_operation.pre_script / post_script` 里的 Groovy 抽成**可复用资产**。对齐参考系统 `ETL处理器管理` 的四个类型：前置 ETL / 后置 ETL / 内置处理器 / 公共代码块。

**为什么值得单开菜单**：脚本是"对三方翻译"的核心资产。内联意味着改一个字段要逐个接口改、无法复用、无法 diff、无法回归。

**数据模型（新增）**

```sql
CREATE TABLE etl_handler (
  id             BIGINT PRIMARY KEY AUTO_INCREMENT,
  code           VARCHAR(64)  NOT NULL COMMENT '标识，仅字母数字下划线',
  name           VARCHAR(200) NOT NULL,
  type           VARCHAR(20)  NOT NULL COMMENT 'PRE/POST/BUILTIN/COMMON',
  script         MEDIUMTEXT   NOT NULL COMMENT 'Groovy',
  version        INT          NOT NULL DEFAULT 1,
  status         VARCHAR(20)  NOT NULL DEFAULT 'DRAFT' COMMENT 'DRAFT/ONLINE/OFFLINE',
  remark         VARCHAR(500),
  created_at     DATETIME     NOT NULL,
  updated_at     DATETIME     NOT NULL,
  UNIQUE KEY uk_code (code)
);

CREATE TABLE etl_handler_version (
  id           BIGINT PRIMARY KEY AUTO_INCREMENT,
  handler_id   BIGINT       NOT NULL,
  version      INT          NOT NULL,
  script       MEDIUMTEXT   NOT NULL,
  published_by VARCHAR(64),
  published_at DATETIME,
  UNIQUE KEY uk_handler_version (handler_id, version)
);
```

**页面结构**：列表（名称 / 标识 / 类型 / 状态 / 版本 / 修改人 / 修改时间）+ 脚本编辑器（Groovy 高亮、变量树、试跑）+ 版本历史 + 上下线。

**本期范围裁剪**：先做 **只读列表 + 编辑器**（能看能改 `script`），版本历史/试跑放 P2。若后端表来不及落地，前端先做灰态占位页，不阻塞 `/services`。

**验收**：新增 `前置ETL` → 在 `/services` 的脚本 Tab 里能下拉选中它（引用关系建立）——**该项依赖后端表，本期只保证页面可打开、可 CRUD**。

### 2.5 调用方应用 · `/apps` ｜ 后端现成

**职责**：网关凭证管理面。业务系统通过 `POST /gw/{connector}/{operation}` 调用，需要 `app_key` + `app_secret` 签名。

**数据源**：`app`（name / app_key / app_secret_enc / allowed_connectors / rate_limit_qps / ip_whitelist / status）

**页面结构**：列表 + 新建抽屉（**创建成功后弹一次性 secret 展示**）+ 编辑。

**关键交互**
- `app_secret` **只在创建时明文显示一次**（库里 AES-GCM 密文）。刷新后只能重置，不能回读。
- `allowed_connectors`、`ip_whitelist` 用多选/标签输入，**不要**让用户手写 JSON
- `rate_limit_qps` 与后端 `carbon-modules/carbon-gateway/src/main/java/com/carbon/modules/gateway/gw/GwRateLimiter.java` 联动

**验收**：创建应用 → 复制 secret（只此一次）→ 用该 secret 签名调网关成功；刷新后页面上不再出现 secret。

### 2.6 流程列表 · `/flows` ｜ **新增，后端现成**

**职责**：编排总台账，**双区（运行区 / 编辑区）在这里切**。

**数据源**：`flow`（code / name / draft_dsl / published_version / status）

**页面结构**
- 顶部 `ReSegmented`：运行区 ｜ 编辑区
  - **运行区**：`published_version > 0` 的流程（已上线生效的版本）
  - **编辑区**：全部流程（含草稿）
- 筛选：名称关键词 / 状态 / 是否已发布
- 列：流程名称、`code`、状态、已发布版本（`0` = 从未发布）、节点数、最后修改时间、操作
- 行操作：**设计**（→ `/flows/design/:id`）/ 试跑（`POST /api/flows/{id}/run-async` 并跳运行详情）/ 版本历史 / 发布（`POST /api/flows/{id}/publish`）/ 删除

**为什么双区放这里**：`draft_dsl` 为空的流程在运行区是空行；拆成两个菜单会长期出现半空页。

**验收**
1. 新建流程 → 出现在编辑区、不在运行区
2. 发布后 → 同时出现在运行区，版本号 = 1
3. 运行区同一条流程多次发布，只出现在运行区一行（版本号取最新）

### 2.7 编排设计器 · `/flows/design/:id` ｜ **新增，后端现成**

**职责**：画布工作台。本期需求（三方节点流程）的最终落点。

**后端接口（全部已具备）**
- 读：`GET /api/flows/{id}`（`draftDsl`）
- 存：`PUT /api/flows/{id}`（更新草稿）
- 校验：`POST /api/flows/validate`，body `{"dsl": "..."}`，返回 `List<ValidationError>`（**全部错误**，不是第一个）
- 试跑：`POST /api/flows/{id}/run`（同步，带 input）
- 发布：`POST /api/flows/{id}/publish?operator=anonymous`
- 版本：`GET /api/flows/{id}/versions`、`POST /api/flows/{id}/rollback`

**三栏布局**

| 栏 | 内容 | 本期范围 |
|---|---|---|
| 左（240px） | 节点面板 | **只启用 4 类**：开始 / 三方服务 / 判断 / 结束（参考系统有 16 类，其余 `docs/09` §12 明确排除） |
| 中（自适应） | **LogicFlow** 画布 | 三方服务=橙色矩形、判断=橙色菱形、结束=蓝紫；连线渲染条件名标签 |
| 右（360px） | 属性面板 | 三方节点 6 组 Tab（见下） |

**属性面板 6 组 Tab（三方服务节点）**

| Tab | 字段 | 校验码 |
|---|---|---|
| 1 选服务 | 连接器 → 接口（级联下拉，`input_schema` 决定入参行） | `MAPPING_INCOMPLETE` |
| 2 入参映射 | `name / type / required / value{kind: VAR\|CONST, ref}` | `PARAM_REQUIRED_MISSING`、`INPUT_CONFLICT` |
| 3 出参映射 | `field / name / jsonPath` | `OUTPUT_NAME_DUPLICATE` |
| 4 降级 | 备用连接器 + 备用接口 + `interruptOnFail` | `FALLBACK_OUTPUT_NOT_SUPERSET` |
| 5 缓存 | `enabled / ttlSeconds / localFirst` | `CACHE_TTL_EXCEEDED`、`CACHE_ON_DISABLED_SERVICE` |
| 6 超时与异常 | `timeoutMs / skipOnTimeout / onError` | `NODE_NAME_TOO_LONG` |

**顶部动作栏**：保存草稿 / 校验 / 单笔试跑 / 发布 / 版本历史 / 适应画布 / 缩放 / 撤销 / 重做

**关键交互（硬要求）**
1. 校验错误**必须定位到节点或连线**（`ValidationError` 带 nodeId → 画布高亮 + 自动居中），不能只弹 toast。
2. 试跑结果**必须回填到画布**：命中节点标绿、失败标红、跳过标灰，点节点看 input/output 快照（对齐参考系统的「节点执行情况」）。
3. 有未保存修改时离开页面要拦截（`onBeforeRouteLeave`）。
4. 出参池全局扁平：选出参名时下拉里已存在的名字置灰（`OUTPUT_NAME_DUPLICATE` 前置拦截）。

**验收**
1. 拖入 三方服务 → 结束 → 连线 → 保存 → 刷新，画布与属性面板完全还原
2. 故意漏填必填入参 → 校验后节点红框 + 面板报 `PARAM_REQUIRED_MISSING`
3. 两个节点出参同 `name` → 校验报 `OUTPUT_NAME_DUPLICATE`
4. 单笔测试 → 节点上出现耗时与状态

### 2.8 版本历史 · `/flows/:id/versions` ｜ **新增，后端现成**

**职责**：`GET /api/flows/{id}/versions` 列版本 + `POST /api/flows/{id}/rollback` 回滚（后端为"指针回退 + 草稿同步"）。

**页面结构**：版本列表（版本号 / 发布人 / 发布时间 / 发布描述）+ **版本对比**（两级：节点级 diff、连线级 diff，对齐参考系统 `节点对比结果:` / `线段对比结果:`）+ 回滚（二次确认，文案写明"会把当前草稿覆盖成该版本"）。

### 2.10 数据源调用明细 · `/call-details` ｜ **新增，后端只有 `/api/logs`**

**职责**：对齐参考系统 `数据源调用明细`，面向**对账 / 排障**，不是给开发看的原始日志。

**数据源**：`invoke_log`（`traceId` `source` `appId` `flowRunId` `connectorId` `operationId` `method` `realUrl` `reqBody` `respStatus` `durationMs` `errCode` `createdAt`）

**与「调用日志」的区别（必须分开的理由）**

| | 数据源调用明细 `/call-details` | 调用日志 `/logs` |
|---|---|---|
| 受众 | 运营 / 对账 | 开发 / 排障 |
| 列 | 数据源服务接口、来源（GW/FLOW/CONSOLE）、返回结果、耗时 | traceId、URL、状态码、错误信息、完整报文 |
| 顶部指标 | 成功率、失败率、失败平均耗时 | 无 |
| 筛选 | 日期范围、接口、来源、仅失败 | traceId、时间、状态码 |

**实现约束**：不新增后端接口，前端在 `GET /api/logs` 上加聚合视图。**注意**：成功率只能对当前页算，是错的 —— 页面必须标注「当前页统计」，或等后端提供 `GET /api/logs/stats`。

### 6.2 顺手修掉的后端 bug

`carbon-modules/carbon-flow/src/main/java/com/carbon/modules/flow/service/impl/FlowServiceImpl.java:47` 的 `BLANK_DSL` 把边写成了 `{"from":"start","to":"end"}`，但 `carbon-framework/carbon-framework-dag/src/main/java/com/carbon/framework/dag/dsl/EdgeDef.java:13` 的字段是 `source`/`target`。因为 `FlowDsls` 的 `ObjectMapper` 配了 `FAIL_ON_UNKNOWN_PROPERTIES=false`，`from`/`to` 会被静默丢弃，`EdgeDef` 的紧凑构造器抛 `边缺少 source 或 target`——**结果是新建的空流程第一次发布会直接失败**。已改为 `source`/`target`。

### 6.4 已知遗留

1. `pnpm install`/`pnpm add` 报 `ERR_PNPM_IGNORED_BUILDS`（`esbuild`、`vue-demi`、`@parcel/watcher`、`@logicflow/core` 的 postinstall 被 pnpm 10 拦了）。已核对：`@esbuild/win32-x64` 的 `esbuild.exe` 存在、`vue-demi` 默认导出即为 vue3，**不影响 dev/build**；真要消掉报错就跑 `pnpm approve-builds`。
2. Windows 上 `pnpm dev` 会失败：`package.json` 的 `dev` 脚本是 `NODE_OPTIONS=... vite` 的 POSIX 写法，`cmd.exe` 不认。绕法：`NODE_OPTIONS=--max-old-space-size=4096 pnpm exec vite`。`build` 脚本同理。
3. 画布坐标不进 DSL（`DagDsl` 只有 nodes/edges/timeoutMs），刷新后按 BFS 自动重排。要保存手工布局得给 `DagDsl` 加 `layout` 字段，属 `docs/09` §3 待办。
4. 设计器本期只开放 开始/三方服务/判断/结束 四类节点；规则集/评分卡/子流程等要等对应资产表。已有的 `SCRIPT`/`LOOP`/`FOREACH`/`DELAY` 节点在画布上是**只读灰框**，能改名称、能连线，但字段（如 `script`）不在面板里编辑，保存时原样写回。
