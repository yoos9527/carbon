> 摘自《Carbon Connector — 三方服务连接器平台 设计文档》v1.8 ｜ 本章包含 §6 API 设计与网关契约 ｜ [← 返回索引](./00-设计总览.md)

## 6. API 设计

统一前缀 `/api`，响应体为 `R<T>`（RuoYi 约定，见 [§4.5](./03-核心链路.md)），`data` 承载业务数据；异常统一 HTTP 200 + `code:500`。

**序列化契约（三个都是「不写就出错」的项，实现见 `carbon-common-web` 的 `JacksonConfig`）**：
- **雪花 id 一律输出字符串**。19 位 id 超过 JS `Number.MAX_SAFE_INTEGER`（2^53-1），`JSON.parse` 会被四舍五入成另一个 id，页面表现是「列表能看、点详情 404」。只对装箱 `Long` 生效，所以 `TableDataInfo.total` 仍是数字，前端分页不用改。
- **时间一律 `yyyy-MM-dd HH:mm:ss`**。`spring.jackson.date-format` 不作用于 `LocalDateTime`，不显式注册就退化成 ISO-8601（`2026-10-27T09:59:31.756`），前端只能自己截字符串。反序列化同步注册，否则请求体回传的时间解析不了。时区见 [§3 时区约定](./02-数据模型.md)。
- **列表不返回大字段**。`GET /api/flows` 显式排除 `draft_dsl`（整张图的 JSON，几十 KB 起步），只在 `GET /api/flows/{id}` 返回。

**分页与参数约定（照搬 RuoYi）**：
- 分页入参：`pageNum`（默认 1）、`pageSize`（默认 10）、`orderByColumn`、`isAsc` → 封装为 `PageQuery`
- 分页出参：`TableDataInfo<T>` = `{ total, rows, code, msg }`
- 列表查询参数封装为 `XxxBo`（含 `searchValue`、`params` 扩展槽）

### 6.1 配置域

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/connectors` | 分页；参数 `keyword, category, status` + `pageNum, pageSize` |
| POST | `/api/connectors` | 新建，返回 id |
| GET | `/api/connectors/{id}` | 详情（含 auth） |
| PUT | `/api/connectors/{id}` | 更新 |
| DELETE | `/api/connectors/{id}` | 逻辑删除（有启用接口时拒绝） |
| PUT | `/api/connectors/{id}/status` | `{status:0\|1}` 启停；启用前校验配置完整性 |
| POST | `/api/connectors/{id}/auth/test` | 主动取 Token / 校验鉴权，返回是否成功与耗时 |
| GET | `/api/connectors/{id}/operations` | 接口列表 |
| POST | `/api/operations` | 新建接口 |
| GET/PUT/DELETE | `/api/operations/{id}` | 详情/更新/删除 |
| POST | `/api/invoke/{connectorCode}/{operationCode}` | **试调**：`{envCode, pathParams, query, headers, body, preScriptOverride, postScriptOverride}` |
| GET | `/api/envs` | 环境列表（默认环境排最前，`vars` 以 JSON 对象返回而非字符串） |
| POST | `/api/envs` | 新建；`{code,name,baseUrlPrefix,vars,isDefault,remark}`。`code` 小写字母开头、`[a-z0-9_-]{2,64}`（服务端转小写）；`baseUrlPrefix` 缺 `http(s)://` 自动补 `http://`、去尾部斜杠；`vars` 只收字符串/数字/布尔，禁写保留键 `code`/`baseUrlPrefix`，总大小 ≤64KB。**表里第一个环境强制为默认** |
| PUT | `/api/envs/{id}/default` | 设为唯一默认（无 body），前端「设为默认」按钮直调 |
| GET/PUT/DELETE | `/api/envs/{id}`、`/api/envs`(DELETE 批量 body=id 数组) | 详情/更新/批量软删。更新时 `vars`、`baseUrlPrefix`、`remark` 传 `null` = 不动，`baseUrlPrefix` 传空串 = 清空。不变式：**只要有环境就恰好有一个默认**——取消默认或删除默认后自动把 id 最小的提为默认 |
| GET | `/api/envs/vars` | 变量摊平视图（渲染上下文预览）：环境 `vars` + 平台注入的 `code`/`baseUrlPrefix`；`code` 省略则取默认环境 |
| GET/POST/PUT/DELETE | `/api/apps[/{id}]` | 应用管理 |
| PUT | `/api/apps/{id}/secret` | 重置密钥（旧 secret 立即失效，明文只返回这一次） |
| GET | `/api/logs` | 分页；`connectorId, operationId, source, traceId, onlyFailed, beginTime, endTime` |
| GET | `/api/logs/{traceId}` | 该 traceId 下的**调用明细**（多行，按时间）+ 每行的 `flowRunId`（可空）。**不含编排步骤**——步骤树由前端再调 `/api/flow-runs/{runId}` |
| GET | `/api/logs/writer/status` | 异步落库器水位：`{queueSize, written, failed, dropped}`（进程内计数，重启归零，别当持久指标用） |
| GET | `/api/logs/partitions` | 分区现状：`{enabled, aheadMonths, retentionDays, partitions:[{name,upperBound}], lastReport}`。运维用它确认「下个月的分区在不在、上次维护到底跑没跑」 |
| POST | `/api/logs/partitions/maintain` | 手动跑一次完整维护（建分区 + 清过期），返回 `{ran, skippedReason, created, dropped, deletedRows, partitions}`；`ran=false` 且 `skippedReason=locked-by-another-instance` 属正常（别的实例在跑） |
| GET | `/api/stats/overview?days=7` | 看板聚合，一次拿全：`counts{connectors,operations,flows,apps,jobs,runningRuns}`、`today`/`window` 两个 `{total,failed,successRate,avgMs,p95Ms}`、`trend[{date,total,failed,avgMs}]`（缺数据的日期补 0）、`sourceMix[{source,total,avgMs}]`、`topSlow[{connectorId,operationId,connectorName,operationName,calls,avgMs,maxMs}]`、`topFailed[{errCode,calls}]`。`days` 夹紧到 1~30 而非报错。失败判定 = `err_code` 非空 |
| GET | `/v3/api-docs/gateway` | 网关 OpenAPI 3，**按当前启用的连接器/接口/已发布流程实时生成**（新增接口不用改文档）。只列启用项；`x-carbon-signature` 给出签名算法与示例；`/gw/health` 在文档里标 `security: []` |

### 6.2 编排域（P2）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/api/flows` | 列表（不含 `draftDsl`）/新建 |
| GET/PUT/DELETE | `/api/flows/{id}` | 读草稿（含 `draftDsl`）/ 存草稿（`dsl` 整体覆盖）/ 删除 |
| POST | `/api/flows/validate` | 传 `dsl` 直接校验，返回 `{valid, errors:[{code,message,nodeIds}]}`；结构化校验失败时 `code` 为 `EDGE_BACKWARD` / `EDGE_CROSSING` / `NO_CONVERGENCE`，`message` 带画布指引。**不挂 flowId**——未保存的草稿也要能校验 |
| POST | `/api/flows/{id}/publish` | `?operator=` → 校验草稿 → 编译注册链路 → 落版本快照 → 移动指针。校验不过按 `CODE: message` 用「；」拼前 5 条返回 |
| POST | `/api/flows/{id}/run` | 同步执行，跑完才返回 `{runId, traceId, status, output, stepCount, startedAt, finishedAt}`。适合一两秒能跑完的流程 |
| POST | `/api/flows/{id}/run-async` | 异步执行，立刻返回 `FlowRun`（`status=RUNNING`）。先 `prepare`（解析版本+落 RUNNING 记录）再进线程池，所以响应里**一定有 id**，前端拿它去连 SSE。队列满（默认 200）时先把该记录收成 `FAILED` 再报错，不留幽灵 RUNNING |
| POST | `/api/flows/{id}/rollback` | body `{version}` → 把发布指针指回该版本，并把 `draft_dsl` 覆盖成该版本 DSL（避免「画布是 v3、跑的是 v1」）。快照按当前校验规则仍不通过时拒绝回滚。幂等：已在该版本直接返回 |
| GET | `/api/flows/{id}/versions` | 版本列表（降序）。发布版本号取 `MAX(version)+1`，不是「指针+1」——回滚后指针会往回走，用指针加一会撞唯一键 |
| GET | `/api/flow-runs` | 运行历史分页；`flowId, status` |
| GET | `/api/flow-runs/{id}` | 运行详情 `{run, steps}`，`steps` 按 `execIndex` 升序 |
| GET | `/api/flow-runs/{id}/stream` | **SSE 进度流**（`text/event-stream`）。事件：`snapshot`（运行记录）→ 若干 `step`（`{nodeId,nodeType,status:RUNNING/SUCCESS/FAILED,durationMs,error}`，节点进出各一条）→ `done`（终态 + 完整 `steps`，收到即断开）。已结束的 id 也能连：先补发缓冲事件再关闭。实时事件是**进程内**总线，多实例下可能收不到 `step`，此时由 1s 一次的库轮询兜底发 `done` |

### 6.3 调度域（P3）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/api/jobs` | 列表（`flowId` 可选过滤，带 `nextFireTimes`）/新建（创建即注册 Quartz） |
| GET/PUT/DELETE | `/api/jobs/{id}` | 详情 / 更新（重注册 trigger）/ 删除 |
| POST | `/api/jobs/{id}/enable`、`/disable` | 启停（禁用即从 `QRTZ_JOB_DETAILS` 摘除） |
| POST | `/api/jobs/{id}/trigger` | 立即执行一次；**未启用时返回 `PARAM_INVALID`**（文案「任务未启用，先启用再立即执行」）——只有 `trigger` 会拦，别误以为 enable 不起作用 |

### 6.4 网关（对外）

网关鉴权链（`GwGuard`，两个入口**逐条一致**）：appKey 存在且启用 → 时间窗 ±5min → 签名 → nonce 未用 → IP 白名单 → 应用 QPS → 连接器白名单。任一条不过抛 `GwRejectedException`，由 `GwExceptionHandler`（`@Order(HIGHEST_PRECEDENCE)`，否则会被管理端 `GlobalExceptionHandler` 吞成 500「服务器开小差了」）统一转 `GwResult`。

| 方法 | 路径 | 说明 |
|---|---|---|
| ANY | `/gw/{connectorCode}/{operationCode}` | 签名鉴权；body 透传；变量从 query + JSON body 顶层采集 |
| GET/POST | `/gw/flows/{flowCode}` | 触发**已发布**编排，**同步**返回 `{runId, status, output, stepCount, flowTraceId}`；body 顶层 + query 作为 flow `input`。`status=SUCCESS` 才回 `code="0"` + HTTP 200，`PARTIAL/FAILED` 回 HTTP 500 但 `data` 里**仍带 `runId`** 可供查明细。应用配了连接器白名单时，会按该流程**实际引用到的**连接器逐个校验（防绕道） |
| GET | `/gw/health` | 无鉴权存活探针：`{status:"UP", time, traceId}`。只回答「进程还在」——不查库、不报版本号（这条路匿名开放，不能泄露有信息量的东西） |
