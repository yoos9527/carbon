# 数据接入平台（Data Service Platform）方案

> 本文是 v1.10 的需求基线与实现方案，取代 `docs/00-设计总览.md` 里「连接器平台」的定位描述。
> 落地顺序见 §10，第一批真实对接供应商为**企查查**（接口事实见 §8，本地 mock 见 §9）。

## 1. 需求基线（已与业务确认，不再改动）

| 项 | 结论 |
|---|---|
| 产品定位 | **数据接入平台**：业务系统只调本系统一个服务，拿到干净的结构化数据 |
| 三层模型 | 供应商 → 接口（前置 ETL + 后置 ETL）→ 编排（接口间依赖）→ 对外数据服务 |
| ETL 形态 | **脚本级自由编程**（Groovy 沙箱），不是声明式字段映射 |
| 异构能力 | 报文加密/签名（脚本）、mTLS/证书（连接器配置）、multipart、异步轮询 —— 都要 |
| 多供应商切换 | **本期不做**（预留路由位，不做 failover/字段互补） |
| 缓存 | 按服务配 TTL；命中记 0 成本 |
| 计量 | 每笔记供应商成本并归到应用，可出账 |
| 原始回包 | **永久存档**（热 3 个月在库，冷数据加密归档） |
| 失败语义 | 单个接口失败不中断流程；成功数据照返；`partial`+`errors[]`；HTTP 恒 200 |
| 脚本作者 | 多人，需要版本化 / 试跑 / Diff / 回滚 / 函数手册 |
| 环境隔离 | 一份配置 + `env` 切 baseUrl 与密钥（不复制三份脚本） |
| 交付形态 | 先单人调通（不做登录/RBAC），量级按 **10 万次/日** 设计 |

## 2. 目标模型

```
供应商（connector）           企查查 / 天眼查 / 内部系统 …  鉴权=连接器级（含 mTLS 证书）
  └─ 接口（operation）         1 个三方 HTTP 接口
       前置 ETL  input → vars（改名/补默认/加签/加密）
       后置 ETL  response → output（解密/清洗/枚举归一/脱敏）
  └─ 编排（flow）             多个接口的依赖关系（DAG），节点间用 vars 传值
  └─ 数据服务（data_service）  对外契约 + 缓存 + 计价 + 计量
业务方  →  POST /gw/ds/{serviceCode}  →  干净结构 + partial/errors + meta
```

职责边界一句话：**接口脚本负责「对三方翻译」，编排负责「依赖与合并」，数据服务负责「对我方稳定」。**

## 3. 与现状的差距

| 能力 | 现状 | 本期要做 |
|---|---|---|
| 前置 ETL | 字段有、执行链通、**前端无编辑器** | 编辑器 + 试跑 + 变量树 |
| 后置 ETL 产出 | 只有 `responseExtract`（JSONPath 扁平抽取） | **`output` 出口**（脚本优先，`response_mode` 显式声明） |
| 加密原语 | md5/sha256/hmac/base64/urlEncode/jsonpath | `aes/rsa/sm2/sm3` + `money/date/mapEnum/coalesce/assertRequired` |
| 传输层证书 | 无 | 连接器级 mTLS（PEM，私钥加密存） |
| multipart | 无 | `body_type=multipart` |
| 编排 UI | 只有运行记录页 | 表单式步骤编排（画布后置） |
| 轮询/并行 | 无 | `POLL` 节点（必做）、`PARALLEL`（后置） |
| 对外契约 | 无 | `data_service` + 入参/出参校验 |
| 缓存 / 计量 / 存档 | 无 | 见 §5 |
| 脚本版本 | 改即生效 | 草稿/发布/版本/Diff/回滚 |
| 部分成功出口 | 有 `PARTIAL` 状态，无 `errors[]` | `/gw/ds/{code}` 固定响应结构 |

## 4. 数据模型变更

新增 5 张表：

```sql
-- 对外数据服务：服务 = 编排 + 契约 + 缓存/计价策略
data_service(
  id, code UNIQUE, name, flow_id,
  in_contract  JSON,      -- 入参契约（字段/类型/必填/枚举）
  out_contract JSON,      -- 出参契约（文档用途 + 产出校验）
  cache_ttl_sec INT DEFAULT 0,   -- 0 = 不缓存
  price_micros BIGINT DEFAULT 0, -- 对外售价（可选，微元）
  status, created_at, updated_at, deleted
)

-- ETL 脚本版本：草稿改不影响线上，发布才生效
ds_script_version(
  id, operation_id, kind ENUM('pre','post'), version INT,
  script LONGTEXT, remark, published_by, published_at,
  UNIQUE(operation_id, kind, version)
)

-- 原始回包归档索引（热表之外）
ds_raw_archive(
  id, service_code, app_id, trace_id,
  params_hash CHAR(64),        -- 入参规范化后 sha256，**不存明文参数**
  created_at, object_key, offset BIGINT, bytes, sha256,
  KEY(service_code, created_at), KEY(params_hash)
)

-- 日汇总（出账用，避免扫明细）
ds_daily_usage(
  id, app_id, service_code, stat_date,
  calls INT, cache_hits INT, cost_micros BIGINT, UNIQUE(app_id, service_code, stat_date)
)

-- 连接器传输层证书
connector_tls(
  id, connector_id UNIQUE,
  cert_pem TEXT, key_pem TEXT,   -- key_pem 用 ENC:v1: 加密
  ca_pem TEXT, verify_host TINYINT DEFAULT 1, created_at, updated_at
)
```

已有表加列：

```sql
connector_operation + response_mode VARCHAR(16) DEFAULT 'extract',  -- extract|script
                    + pre_script_draft  LONGTEXT,   -- 草稿；pre_script 为线上生效版
                    + post_script_draft LONGTEXT
invoke_log          + cost_micros BIGINT DEFAULT 0,
                    + cache_hit TINYINT DEFAULT 0,
                    + service_code VARCHAR(64)
```

DSL 新增节点 `POLL`（见 §6.5），`PARALLEL` 留到 P3 之后。

## 5. 运行时链路

### 5.1 对外入口（业务方唯一需要记的东西）

```
POST /gw/ds/{serviceCode}
Header: X-App-Key / X-Timestamp / X-Nonce / X-Sign   （沿用现有应用签名）
Body:   契约里 in_contract 定义的字段
GET  /gw/ds/{serviceCode}/doc      返回契约（JSON Schema + 示例），供业务方自助接入
```

处理链：

1. 应用鉴权（已有 `GwGuard`：appKey → 时间窗 → 签名 → nonce → IP → QPS → 白名单）
2. **契约校验**：必填/类型/枚举/长度，失败回 `400` + 字段级 `errors[]`（不进入编排）
3. **缓存查找**：`ds:cache:{serviceCode}:{sha256(规范化入参)}`，命中直接返回（`meta.cacheHit=true`）
4. **single-flight**：同 key 并发只放一个请求进编排，其余等待复用结果（避免 10 个业务方同时打三方）
5. 执行编排：节点失败不中断（`OnError.CONTINUE`），汇总失败清单
6. 异步写：`invoke_log`（含 `cost_micros/cache_hit/service_code`）+ 归档队列 + `ds_daily_usage`

### 5.2 响应结构（固定，HTTP 恒 200）

```json
{
  "code": "0",
  "msg": "OK",
  "data": { "company": { "name": "..." } },
  "partial": true,
  "errors": [
    { "node": "risk", "code": "PROVIDER_TIMEOUT", "message": "风险接口超时（3 次重试后）" }
  ],
  "meta": {
    "traceId": "b7f3c2d1e0a9",
    "cacheHit": false,
    "elapsedMs": 812,
    "costMicros": 1200000,
    "asOf": "2026-10-27 21:05:12"
  }
}
```

规则：

- `data` 里**成功节点的字段照常返回**，缺的字段**不出现**（不填 `null`、不填假值）
- `partial=true` 只表示「有可选节点失败」，`code` 仍为 `0`
- 必填节点失败（契约里标 `required: true`）→ `code` 为对应错误码，HTTP 仍 200，`data` 带已成功部分
- 业务方判断：`code=="0" && !partial` 才可整体采信

### 5.3 缓存

- key 用**规范化入参**的 sha256（排序 key、去空白、忽略 `noCache`），避免 `{a,b}` 与 `{b,a}` 打两次三方
- TTL 配在 `data_service.cache_ttl_sec`；`0` = 不缓存
- 业务方可传 `noCache=true` 强制穿透（仍计量、仍存档）
- 只缓存 `code=="0" && !partial` 的结果（部分成功的缓存会污染后续调用）
- 缓存值附带 `cachedAt/costMicros`，命中时 `meta.costMicros=0`、`meta.cacheHit=true`

### 5.4 计量与出账

- `cost_micros` = 供应商单价（配置在接口上 `operation.cost_micros`，默认 0）× 实际调用次数
- 一次对外调用若打了 3 个接口，成本是三者之和；缓存命中的节点不产生成本
- 日汇总写 `ds_daily_usage`，管理端按 `app × 服务 × 月` 出报表
- **成本对业务方透明**：`meta.costMicros` 直接返回（内部先自用，后续可配开关）

### 5.5 存档（永久）

- **热数据**：`invoke_log` 保留 3 个月（含 `resp_body` 截断 64KB），按月分区
- **冷数据**：每月把到期分区导出 `jsonl.gz`（AES-GCM 加密，key 由 `carbon.crypto.master-key` 派生）到对象存储/本地目录，文件名 `raw/{yyyyMM}/{service}.jsonl.gz`，索引写 `ds_raw_archive`
- 归档后删除分区，**保留期永久**；按 `traceId` / `params_hash` 可定位到归档文件 + offset
- 敏感值不入索引：`ds_raw_archive` 只存 `params_hash`，不存明文手机号/身份证

## 6. ETL 脚本契约

### 6.1 变量

| 作用域 | 前置 ETL | 后置 ETL |
|---|---|---|
| `input` | 业务入参（只读） | 业务入参（只读） |
| `vars` | 可写，作为渲染源 | 可写 |
| `auth` | 鉴权配置明文（只读） | 只读 |
| `env` | 环境变量（只读） | 只读 |
| `response` | — | `{status, headers, body}` |
| `output` | — | **可写：对外结果** |

### 6.2 铁律

1. **密钥不进脚本**：只从 `auth` 读（库内 `ENC:v1:` 加密存储）
2. **脚本无 IO**：不能发 HTTP、不能读文件；加解密是纯函数
3. **`output` 必须符合契约**：发布前用试跑结果校验 `out_contract`，不符则拒绝发布
4. **缺变量必须显式报错**：`input.x ?? 'default'`，不允许静默空串（现有渲染器已强制）

### 6.3 utils 白名单（在现有基础上新增）

```
摘要/编码  md5 sha1 sha256 sm3 hmacSha1 hmacSha256 base64Encode base64Decode hexEncode hexDecode
           urlEncode urlDecode
对称加密   aesEncrypt(text, key, mode='CBC'|'GCM', iv=null, padding='PKCS5Padding') / aesDecrypt
非对称     rsaSign(data, privateKey, algo='SHA256withRSA') rsaVerify rsaEncrypt rsaDecrypt
           sm2Sign sm2Verify sm3
结构       jsonpath toJson parseJson
类型转换   money(text) -> {value, unit}     date(text, from?) -> 'yyyy-MM-dd'
           mapEnum(v, dict, default)        coalesce(...)  str num bool
校验       assertRequired(v, name)  regex(s, p)  replaceAll(s, p, r)
其它       now() timestamp() uuid() randomInt(a,b) mask maskIdCard maskPhone
```

实现约束：`aes/rsa/sm2` 用 BouncyCastle，**只暴露 `utils` 方法**，不把 BC 的类加入脚本白名单。

### 6.4 示例：企查查（前置加签 + 后置清洗）

```groovy
// 前置 ETL：key 走 query，Token/Timespan 走 header
vars.timespan = utils.timestamp()                                   // 秒
vars.token    = utils.md5(auth.appKey + vars.timespan + auth.secretKey).toUpperCase()
vars.searchKey = (input.creditCode ?: input.companyName).trim()
utils.assertRequired(vars.searchKey, 'companyName 或 creditCode')
```

```groovy
// 后置 ETL：QCC 的 Status 是字符串 "200"，业务错误也在 200 里
if (response.body.Status != '200') {
    utils.error('PROVIDER_BUSINESS_ERROR', response.body.Message ?: '企查查返回失败')
}
def r = response.body.Result
output = [
  company: [
    name        : r.Name,
    creditCode  : r.CreditCode,
    regNo       : r.No,
    qccCode     : r.QccCode,
    status      : utils.mapEnum(r.Status, [在业:'ACTIVE', 存续:'ACTIVE', 注销:'CANCELED',
                                          吊销:'REVOKED', 迁出:'MOVED', 停业:'SUSPENDED'], 'UNKNOWN'),
    legalPerson : r.OperName,
    regCapital  : utils.money(r.RegisteredCapital + r.RegisteredCapitalUnit),
    establishDate: utils.date(r.StartDate),
    regAuthority: r.BelongOrg,
    companyType : r.EconKind,
    address     : r.Address,
    businessScope: r.Scope,
    industry    : [code: r.Industry?.Code, name: r.Industry?.Name],
    tags        : r.TagList?.collect { it.Name } ?: [],
    updatedAt   : r.UpdatedDate
  ]
]
```

### 6.5 POLL 节点（异步类供应商）

```json
{ "id": "p1", "type": "POLL",
  "connector": "some-vendor", "operation": "query-task",
  "input": { "taskId": "{{vars.s1.taskId}}" },
  "until": "response.body.status == 'DONE' || response.body.status == 'FAILED'",
  "intervalMs": 5000, "maxAttempts": 60, "timeoutMs": 300000,
  "onError": "CONTINUE" }
```

### 6.6 已知缺口：一个供应商两个密钥怎么存

企查查要 `key`（AppKey）与 `secretKey` **两个值**同时参与签名，而 `AuthConfigCodec` 目前只对
固定字段加密（`api_key` 只加密 `value`）。临时可用（AppKey 本就不算密钥，可明文）：

```json
{ "authType": "api_key", "config": { "in": "header", "name": "X-Unused",
                                          "appKey": "qcc_mock_key", "value": "<secretKey>" } }
```

P1 要做成正式能力：`connector_auth` 支持「自定义敏感字段名单」——配置里标 `encrypt: true` 的键
统一走 `ENC:v1:`，而不是靠 `SECRET_KEYS` 按鉴权类型硬编码。

## 8. 企查查对接事实（2026-10 抓取的官方文档）

| 服务 | 接口地址 | 请求方式 | Query |
|---|---|---|---|
| 企业工商信息 | `https://api.qichacha.com/ECIInfoVerify/GetInfo` | GET | `key`, `searchKey`（信用代码/名称/QccCode） |
| 企业风险 | `https://api.qichacha.com/ECIInfoOverview/GetInfo` | GET | `key`, `searchKey` |
| 司法案件 | `https://api.qichacha.com/JudgmentDocCheck/GetList` | GET | `key`, `searchKey`, `pubYear`, `caseIdentity`(1被告/2原告), `caseStatus`(1待结案/2已结案), `keyWord`, `pageIndex`, `pageSize`(≤20) |

**鉴权（三个接口一致）**

```
Header  Token:    MD5(key + timespan + secretKey).toUpperCase()   // 32 位大写
Header  Timespan: 精确到秒的 Unix 时间戳
Query   key:      AppKey
```

**响应包（统一）**

```json
{ "Status": "200", "Message": "", "Result": { ... }, "OrderNumber": "..." }
```

`Status` 是**字符串**：`200` 成功；`101`/`102` 等为失败（鉴权/余额/参数），业务错误同样回 200 外层 + 内层标记 —— 后置 ETL 必须判 `Status`，不能只看 HTTP。

**关键字段映射**（QCC → 我方契约，详见 §7）

| 我方 | QCC 字段 |
|---|---|
| `company.status` | `Status`（在业/存续/注销/吊销/迁出） |
| `company.regCapital` | `RegisteredCapital` + `RegisteredCapitalUnit` + `RegisteredCapitalCCY` |
| `company.legalPerson` | `OperName` |
| `company.industry` | `Industry.Code/Name` |
| `partners[]` | `Partners[]`（股东比例在 `StockPercent`） |
| `penalty[]` | `Penalty[]`（风险扫描接口） |
| `exceptions[]` | `Exceptions[]` |
| `shixin[]` | `ShiXinItems[]` |
| `zhixing[]` | `ZhiXingItems[]` |
| `legal-cases.items[]` | `JudgmentDocCheck` 的 `Data[]`（`CaseName/CaseNo/CaseReason/Amount/JudgeResult/JudgeDate/PartyList`） |

## 11. 默认参数

## 12. 安全与合规

- 三方密钥只存在 `connector_auth.config`，`ENC:v1:` 加密；脚本通过 `auth.*` 读取，**永远不出现在脚本与日志里**
- mTLS 私钥同策略加密存储；`connector_tls` 只允许管理员面读取掩码
- 原始回包属个人信息 → 归档加密 + 访问审计（谁下载了哪个月的归档）
- `ds_raw_archive` 只存 `params_hash`，不存明文查询参数
- 出参默认脱敏：`maskIdCard/maskPhone` 由后置 ETL 强制调用（契约校验会检查声明）
