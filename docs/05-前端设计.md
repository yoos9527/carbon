## 5. 前端设计

### 5.0 现状与范围

`carbon-ui` 已落地（Vue3 + Element Plus + TS，见 §5.2）：配置域 P1 五页 + P3 调度页 + P2 运行历史页 + **首页看板**已实现，画布待建。本章按「现在能对得上的后端」写，不再描述尚未存在的接口。

- 前端不是 Maven 模块，`pnpm build` 产物复制到 `carbon-admin/src/main/resources/static/`，与后端同包发布（§9.8）。
- 分期：**P1** 配置域 6 个页面（连接器 / 接口+试调 / 环境 / 应用 / 日志 / 登录占位无）；**P2** 编排画布 + 看板 + 网关文档页；**P3** 调度页 + 平台设置。
- 本章的「后端状态」列只标两态：`已实现` / `待补`。待补项汇总在 §5.10，是前端开工的解锁清单。

### 5.1 路由与页面

**P1（配置域）**

| 路由 | 页面 | 依赖接口 | 后端状态 |
|---|---|---|---|
| `/connectors` | 连接器列表：搜索、分组、启停、复制、删除 | `GET /api/connectors`、`POST /api/connectors/{id}/copy`、`PUT /api/connectors/{id}/status`、`DELETE /api/connectors` | 已实现（复制弹出的副本为停用态，避免「复制即多一个生产入口」） |
| `/connectors/:id/edit` | 四 Tab：基本信息 / 鉴权 / 默认 Header / 超时重试 | `GET /api/connectors/{id}`、`PUT /api/connectors/{id}`、`POST /api/connectors/{id}/auth/test` | 已实现（鉴权 Tab 的自检按钮待补前端） |
| `/connectors/:id/operations` | 接口列表（挂在连接器下） | `GET /api/connectors/{connectorId}/operations` | 已实现 |
| `/connectors/:id/operations/:opId` | **接口编辑 + 试调**（核心页） | `GET/PUT /api/connectors/{connectorId}/operations/{id}`、`POST /api/invoke/{connectorCode}/{operationCode}` | 已实现（变量扫描、脚本试跑待补） |
| `/envs` | 环境变量：列表 + 新建/编辑（键值带类型选择：字符串/数字/布尔）+ 设为默认 + 删除 | `GET/POST /api/envs`、`PUT/DELETE /api/envs[/{id}]`、`PUT /api/envs/{id}/default`、`GET /api/envs/vars` | 已实现（变量扫描待补） |
| `/apps` | 应用管理：AppKey、Secret 一次性显示 + 重置、连接器白名单、限流、IP 白名单 | `GET/POST /api/apps`、`PUT /api/apps/{id}`、`PUT /api/apps/{id}/secret`、`PUT /api/apps/{id}/status`、`DELETE /api/apps/{id}` | 已实现 |
| `/logs` | 调用日志：筛选 + 详情抽屉（含「上下游耗时」与失败原因列） | `GET /api/logs`、`GET /api/logs/{traceId}`、`GET /api/logs/writer/status` | 已实现 |

**P2**：`/flows`（列表）、`/flows/:id/design`（画布）、`/flows/:id/runs`（运行历史，**已实现**：列表 + 详情抽屉 + **运行中自动连 SSE 看实时步骤**）、`/welcome`（首页即看板，**已实现**：KPI 卡 + 7/30 天趋势 + 来源占比 + 慢接口/错误码 TOP5）、`/docs`（网关接入文档，后端 `GET /v3/api-docs/gateway` **已就绪**，页面待做：可直接用 Swagger UI/Redoc 挂上，不必自己写渲染）。
**P1 连接器编辑页待补**：粘贴鉴权配置后点「自检」调 `POST /api/connectors/{id}/auth/test`，把 `ok/latencyMs/error` 直接显示在表单下方（后端已就绪）。注意 `expiresIn` 是字符串（全局 `Long→String` 序列化），展示前 `Number()`；token 类第二次点会命中缓存（`latencyMs≈0`），别把它当成「配置没生效」。

**操作日志页（待做）**：`GET /api/oper-logs` 已实装（后端切面自动记录，无需前端埋点）。页面建议做成只读表格：模块 / 动作 / 方法 / 操作人 IP / 结果 / 耗时 / 时间，抽屉里展开 `params`。它是目前**唯一**能回答「昨天谁把鉴权改坏了」的地方——没有登录，`clientIp` + `userAgent` 就是全部线索。

**P3**：`/jobs`（调度，**已实现**：列表/启停/立即执行/下次触发时间预览）、`/settings`。

**三页的两条共用规则**（踩过坑才写进约定）：
- **id 当字符串用**。后端 `Long` 已序列化成字符串（雪花 id 超 JS 安全整数），前端类型写 `string`，`el-table` 的 `row-key` 也用 `String(row.id)`。
- **`triggerType` 存小写字面量**：`manual`（控制台触发）/ `job`（调度触发），不是 `CONSOLE` / `JOB`。

> 不设 `/login`：平台不做登录（§7.5），访问控制交给 Nginx/内网。路由守卫只留一个可插拔的 `beforeEach` 空实现，将来接 SSO 时不改页面。

### 5.2 工程约定

- 栈：Vue 3.5 + TS + Vite + Element Plus + Pinia + UnoCSS；编辑器 Monaco；看板 ECharts 6；画布 LogicFlow（P2）。目录规范见 §9.7，不在此重复。
- **响应约定**：后端统一 `R{code, msg, data}`，`code=200` 为成功。`request.ts` 里只做三件事：`code!==200` 抛业务异常并 `ElMessage.error(msg)`；`401/403` 单独文案（网关错误码见 §5.9）；把响应头 `X-Trace-Id` 挂到错误对象上，便于用户复制给后端排查。
- **分页约定**：请求 `{pageNum, pageSize, orderByColumn?, isAsc?}`，响应 `TableDataInfo{total, rows}`；`useTable` hook 统一管 loading / total / 翻页。
- **雪花 id 是字符串**：后端已用 `ToStringSerializer` 输出，前端 TS 类型一律 `string`，禁止 `Number(id)`（超过 2^53 会丢精度）。
- **接口前缀只有一个来源**：`src/utils/http/index.ts` 导出的 `API_BASE`（读 `VITE_APP_BASE_API`，缺省 `/api`），axios 的 `baseURL` 与 SSE 的 `EventSource` URL 都用它。api 模块里只写 `/envs` 这种相对路径。**曾经漏了 `baseURL`**，请求打到前端静态服务器拿回 `index.html`，表现是「所有列表都加载失败」，而 `curl` 打后端一切正常——排查这类问题先看浏览器 Network 里请求的真实 URL。
- **环境选择器**：试调与日志筛选共用一个全局 `currentEnv`（Pinia），不必每个页面各做一份。
- **时间**：后端返回 `yyyy-MM-dd HH:mm:ss`（`LocalDateTime`），前端不做时区换算，只做「相对时间」显示（如 `3 分钟前`）。

### 5.3 连接器列表页

列：名称 / 编码（等宽字体）/ 分组 / 鉴权类型（Tag）/ 接口数 / 状态开关 / 更新时间 / 操作。

- 搜索：`keyword` 同时匹配名称与编码；`category` 下拉（从当前页数据聚合，不额外造字典表）。
- 状态开关：**乐观更新**，请求失败回滚并提示；停用不影响已发布流程（编排侧只认 `status=1`）。
- 删除：二次确认弹窗里显示该连接器下的接口数量，提示「N 个接口将一起删除，调用它的编排会失效」。后端已有「有启用接口时拒绝」的约束，前端把错误原文透出即可。
- 空态：区分「一个都没有」（引导新建）与「筛选无结果」（清空筛选）。

### 5.4 连接器编辑页（四 Tab）

| Tab | 字段 | 说明 |
|---|---|---|
| 基本信息 | `code`、`name`、`category`、`baseUrl`、`remark` | `code` 保存后**不可改**（它是网关路径与编排引用的一部分）；`baseUrl` 允许 `{{env.xxx}}`，旁边给「按当前环境渲染后」的预览 |
| 鉴权 | `authType` + `auth.config` | 六种：`none` / `api_key` / `basic` / `bearer` / `oauth2_cc` / `login_token`，动态表单见下 |
| 默认 Header | `defaultHeaders` | 键值表格，键不区分大小写去重 |
| 超时重试 | `timeoutMs`、`retry.maxAttempts`、`retry.backoffMs`、`retry.backoffMultiplier`、`retry.retryOn` | 默认 `0` 次重试；`retryOn` 为空则只重试 5xx 与超时。**POST 默认不重试**（防重复下单），要在弹窗里显式勾「该接口幂等」 |

鉴权动态表单：

- `api_key`：`in`（header/query）、`name`、密钥值（密文，回显为 `******`，只有「重置」没有「查看」）
- `basic`：`username`、`password`（密码密文）
- `bearer`：`token`（密文）
- `oauth2_cc`：`tokenUrl`、`clientId`、`clientSecret`（密文）、`scope`
- `login_token`：`loginUrl`、`method`、`bodyTemplate`、`tokenPath`、`expiresInPath`

### 5.5 接口编辑 + 试调页（核心页）

```
┌──────────────────────────────────────────────────────────────────┐
│ 面包屑：CRM 连接器 / 查询订单      [保存] [只渲染] [发送] [生成 cURL]│
├──────────────────────────────┬───────────────────────────────────┤
│ 左：请求定义（Tab）           │ 右：试调面板                       │
│  ● 基本 ○ Query ○ Header     │  环境: [dev ▾]                    │
│  ● Body ○ 前置脚本           │  ┌ 入参表单（按模板变量生成）────┐ │
│  ○ 后置脚本 ○ 响应抽取        │  │ orderId  [__________]        │ │
│                              │  │ qty      [3_________]        │ │
│  Body：Monaco(JSON)          │  └──────────────────────────────┘ │
│  {"orderId":"{{input.orderId}}","qty":{{input.qty}}}             │
│                              │  ┌ 响应 Pretty│Raw│Headers│Timing ┐│
│                              │  │ {"echoOrderId":"B-1", ...}    ││
│                              │  └──────────────────────────────┘│
│                              │  耗时 53ms · provider 200 · traceId│
└──────────────────────────────┴───────────────────────────────────┘
```

- **入参表单**：按模板里的 `{{input.xxx}}` 自动生成。当前后端**没有**变量扫描接口，P1 先用前端正则扫描 `{{input.*}}` 应急，等 §5.10 里的 `variables` 接口补上后改为以后端为准（后端要知道引用了哪些变量，才能做「参数缺失」前置校验）。
- **只渲染（dryRun）**：调同一个接口但带 `"dryRun": true`，响应里 `sentRequest{method,url,headers,body}` 直接展示「将要发出的请求」，不发三方。这是排查模板问题最快的路径。
- **发送**：`{"input":{...},"headerOverrides":{...}}`，环境由页面选择器带在 `envCode` 上。
- **响应面板**：Pretty / Raw / Headers / Timing 四视图；`truncated=true` 时顶部挂一条「响应超过 64KB 已截断」的警示条。
- **抽取表格**：字段名、JSONPath、默认值、是否必填；「预览」用上次响应在前端求值。**必须标注「预览仅供参考」**——前端 jsonpath 库与后端 Jayway 语义有差异（后端禁 `$..` 递归下降），最终取值以试调结果里的 `extracted` 为准。
- **脚本**：Monaco + Groovy 高亮；沙箱白名单（`java.util.*` / `java.time.*` / `java.time.format.*` / `groovy.json.*` / `java.math.BigDecimal`）在编辑器右侧常驻提示，避免用户写完才发现被拦。脚本试跑接口待补。
- **生成 cURL**：以后端 `sentRequest` 为唯一来源拼装，敏感 header 值替换为 `$CARBON_SECRET`。

### 5.6 日志页

- 筛选：`source`（CONSOLE/GW/FLOW）、`connectorId`、`operationId`、`traceId`、`success`、时间区间。
- 列：时间 / 来源 / 连接器.接口 / 状态码 / 耗时 / 结果（成功/错误码 Tag）/ traceId。
- 详情抽屉：请求报文、响应报文（均为脱敏后文本，等宽字体 + 折叠）、`errorCode`/`errorMsg`、`providerStatus`、耗时、traceId 一键复制；`flowRunId` 非空时给一个「查看编排步骤」链接跳到 `/flows/:id/runs?runId=...`（**不在此页直接查流程表**——`carbon-invokelog` 是叶子模块，见 §9.3 硬约束）。
- 写入器状态：`GET /api/logs/writer/status` 的 `dropped` 计数非零时，页头显红条「有日志因队列满被丢弃」——这是运维信号，不该藏在详情里。

### 5.7 编排画布（P2）

- 布局：左节点面板（拖拽）/ 中画布 / 右属性面板 / 顶栏（校验 · 试跑 · 发布 · 版本）。
- 节点类型（与后端 `type` 字段严格一致）：`START`、`END`、`CONNECTOR_CALL`、`CONDITION`、`LOOP`、`FOREACH`、`SCRIPT`、`DELAY`。
- 连线规则（前端拦截 + 后端二次校验）：禁止自环；**禁止回边**；**禁止交叉边**；`CONDITION` 出边必须标 `true`/`false`。无 `GOTO`：重复执行统一用 `LOOP`（属性面板只填「最多几次」+「继续条件」）。
- 校验码 → 高亮映射（与后端 `ValidationCode` 对齐）：`EDGE_BACKWARD`（高亮该边 + 提示改用 LOOP）、`EDGE_CROSSING`、`NO_CONVERGENCE`（同时高亮两个分支末端与预期汇聚点）、`BRANCH_EDGE_MISMATCH`（`CONDITION` 的出边与 `branches` 不一致——这类图能画出来但编译会错）、`MISSING_*` / `DUPLICATE_ID` 等。
- 试跑：两个入口并存——`POST /api/flows/{id}/run`（同步，跑完才返回结果）与 `POST /api/flows/{id}/run-async`（立刻返回 `status=RUNNING` 的记录）。画布用后者，拿 `run.id` 连 `GET /api/flow-runs/{id}/stream` 逐节点点亮（`step` 事件是节点进/出各一条），`done` 到了再回查一次落库明细。
- 版本回滚：`POST /api/flows/{id}/rollback` body `{version}`，回滚后草稿与指针一起变，所以画布需要重新 `GET /api/flows/{id}` 拿 `draftDsl`。

### 5.8 调度页（P3）

列表：`name` / 关联流程或连接器接口 / cron（人类可读 + 原文）/ 状态 / 上次触发 / 下次触发 / 操作（启停、立即执行、编辑、删除）。cron 输入框提示 Quartz 是 **6 段**（秒 分 时 日 月 周），与 Linux crontab 5 段不同，非法表达式由后端返回 `PARAM_INVALID`，前端直接透出原文。

### 5.9 统一交互规范

| 场景 | 处理 |
|---|---|
| 加载 | 表格用 `v-loading`；抽屉/弹窗内的详情用骨架屏，避免「先空后闪」 |
| 空态 | 区分「还没数据」与「筛选无结果」，两者文案与主按钮不同 |
| 危险操作 | 删除/停用/重置 Secret 一律二次确认；重置 Secret 需在弹窗里输入 AppKey 全名 |
| 错误码 | 网关错误码（`SIGN_INVALID` / `RATE_LIMITED` / `APP_FORBIDDEN` 等）在日志详情里显示中文解释 + 原码，不只显示码 |
| 表单校验 | blur 时校验字段格式，submit 时校验整体（后端 Bean Validation 的文案直接透出，不重写） |
| 国际化 | P1 只做中文，文案集中放 `lang/zh_CN`，不散落在模板里 |
