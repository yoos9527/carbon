> 定位：**连接器平台**——用页面配置的方式接入外部三方服务，把「URL + 鉴权 + 参数 + 报文」沉淀为可复用的连接器与接口，
> 业务系统只按名称调用平台网关，不接触三方地址与密钥。同时提供 DAG 编排与定时调度能力。

## 术语表

| 术语 | 含义 |
|---|---|
| 连接器 `connector` | 一个三方系统的接入配置：基址、鉴权方式、公共头、超时/重试策略、限流 |
| 接口 `operation` | 连接器下的一个具体动作：method / path / 参数位置 / body 模板 / 响应抽取规则 |
| 环境 `env` | 一套变量集合（dev/test/prod），同名接口在不同环境指向不同基址与凭据 |
| 应用 `app` | 调用方身份，持有 `appKey`/`appSecret`，被授权可调用哪些连接器接口 |
| 试调 | 平台页面上对某个接口发起的一次调试调用，带完整请求/响应与链路耗时 |
| 抽取 | 用 JSONPath 把三方响应里的字段映射进 `vars`，供后续节点与返回值使用 |
| 表达式核 | `{{}}` 占位符与 DAG 条件里 `a.b == 1` 这类单行求值，默认由 Aviator 承担 |
| 沙箱 | Groovy 前后置脚本的执行环境，靠白名单 import + `SecureASTCustomizer` + 超时中断约束 |
| 编排 / flow | 由节点与边组成的自动化流程，可版本化发布、定时触发、手动试跑 |
| 节点 `node` | 编排里的一步，8 种类型见 §4.7 |
| 变量池 `vars` | 一次调用/一次编排运行内共享的 `Map<String,Object>`，各层只通过它通信 |
| chain | LiteFlow 里一条已注册的可执行流程，本平台一版本一条：`flow:{id}:v{n}` |
| traceId | 贯穿一次调用（含编排内所有节点）的链路 ID，日志与步骤表都以它串联 |
| KEK | 密钥加密密钥，来自环境变量 `CARBON_MASTER_KEY`，用于 AES-256-GCM 包裹 `appSecret` |
| single-flight | 同一连接器并发取 token 时只放行一个请求，其余等结果（Redis 锁 + 结果缓存） |

## 1. 决策基线

| 维度 | 选定 | 理由 |
|---|---|---|
| 产品定位 | 连接器平台（非 Postman 精简版） | 核心价值是"把三方服务封装成企业内可复用能力"，而非个人调接口工具 |
| **工程结构** | **Maven 多模块，对齐 RuoYi-Vue-Plus 5.X**：`admin` / `common`（基础设施）/ **`framework`（自研二方包）** / `modules`（业务域）/ `extend` | 团队零学习成本；技术能力与业务代码按“能否脱离本项目复用”硬隔开，详见 [§9](./01-总体架构.md) |
| 后端 | Spring Boot 3.5.x / **Java 21（LTS）** / MyBatis-Plus / MySQL 8 / Redis 7（Redisson） | 21 与 17 功能上零差异，选 21 是为了 `sealed` + `record` + switch 模式匹配——DSL 的 7 种节点可写成密封接口，编译器强制穷尽，把“文档约定”变成“编译期保证”；RuoYi 5.6.2 的 `common-*` 无 17-only 依赖，可直达。虚拟线程暂不开启，理由见 [§9.9](./01-总体架构.md) |
| 前端 | Vue3.5 + TS + Vite + Element Plus + Pinia + Monaco Editor + LogicFlow + ECharts | 目录规范对齐 `plus-ui`；Element Plus 与 LogicFlow 均为 Vue3 原生 |
| 平台登录 | 不做（内部工具） | 由 Nginx/内网访问控制兜底，见 [§7.4](./07-安全运维与交付.md) 风险 |
| 调用入口 | 平台试调 + 对外网关 + DAG 编排 + Quartz 调度 | 三类使用场景：配置期调试、业务侧调用、自动化流转 |
| 三方鉴权 | None / ApiKey / Basic / Bearer / OAuth2 ClientCredentials / 自定义登录换 Token | 覆盖国内主流三方服务形态 |
| 加工深度 | `{{var}}` 模板 + JSONPath 抽取 + Groovy 前后置脚本 | 透传不够用、脚本更灵活，二者结合 |
| 渲染与表达式 | **壳自研**（`TemplateRenderer`，输出 JSON 树/URL/header，兼顾表单元数据） + **核可插拔**（默认 Aviator，兜底自研） | 无开源件同时满足「JSON 结构化 + 表达式 + 沙箱 + 可枚举变量」，详见 [§4.2](./03-核心链路.md) |
| 脚本引擎 | Groovy 4.0.x（≥ 4.0.21）+ 沙箱加固 | 团队熟悉度最高，与 Java 互通最好；Groovy 3.x 在 JDK 21 上有已知坑，因此版本下限硬约束 |
| 编排模型 | DAG 可视化画布（LogicFlow），**限结构化树形图**（禁回边、禁交叉边） | 分支必须汇聚、重复执行用 `LOOP` 框：画布可读、可校验、可编译成 EL |
| 编排引擎 | **LiteFlow core 封装**：`carbon-framework-dag` = DSL→EL 编译 + chain 注册 + 步骤映射 | 买执行器内核（重试/超时/并行/步骤信息/事件回调开箱），省约 1000–1300 行；代价是表达力收敛为树，详见 [§9.9](./01-总体架构.md) |
| HTTP 客户端 | Apache HttpClient 5（显式关自动重试与重定向） | 连接池可控、池满快速失败；不带 Kotlin 运行时，详见 [§9.9](./01-总体架构.md) |
| 调度 | Quartz JDBC 集群 + `JobHandler` 适配层 | 多实例安全、动态 cron；不引 SnailJob 以少一个部署单元，日后换调度中心只改适配层 |
| 网关鉴权 | AppKey + HMAC-SHA256 签名 | 平台不做用户登录，但对外必须可鉴权、可审计、可限流 |
| 主键 / 响应 / 转换 | 雪花 ID、`R<T>`、Bo/Vo + MapStruct-Plus、`BaseMapperPlus` | 照搬 RuoYi 约定，见 [§9.5](./01-总体架构.md) |
| 交付 | P0 骨架 → P1 连接器+网关 → P2 DAG 编排 → P3 调度+观测 | 每阶段可独立验收上线 |
